## Observed routing versus proposed conversation policy

The four named examples were tested locally against the pure current-turn classifier. They are routing observations. Answer quality and context use need an independent model evaluation.

| Scenario | Current behavior or risk | Target policy |
|---|---|---|
| A · Scores → “Who scored the goals?” | First turn enables `sports`. Follow-up disables Search despite history text being present. Prior sources are absent from the model context. | Resolve the match and date from recent turns. Reuse cited scorer evidence if present and relevant, otherwise require Search. |
| B · Scores → explicit Belgrade weather | Second turn enables `weather` and names Belgrade. Old sports text remains in the six-message window. Location instruction prioritizes the current turn. | Treat as a topic switch. Use Belgrade and the requested date. Exclude unrelated football evidence. |
| C · Scores → “What is the forecast for tomorrow?” | `weather` triggers. No location is explicit and the UI tends to supply Belgrade by default. A model may use this even if the user meant a match forecast. | Clarify forecast type or place when the context is insufficient. Resolve only if recent turns establish an unambiguous referent. |
| D · Databases → “Translate your answer into English” | Neither turn needs Search. Previous assistant summary can carry the answer if inside the window. The language resolver can direct English. | Supply the relevant previous complete text and translate it. Avoid a fresh answer or new facts. |
| General knowledge, technical, business, maths | Broad ordinary generation is available. Some keywords route more aggressively than freshness warrants. | Use ordinary reasoning by default. Require evidence where factual freshness matters, with no vertical-specific prompt required. |
| Sports, weather, travel, current information | Scores/weather patterns help, but ambiguous terms and relative dates stay lexical. | Model may choose tools within the application’s evidence policy. Anchor local day/time only when relevant and confirm location when needed. |
| Writing, rewriting, creative, translation | Anchored exclusions can suppress valid mixed requests. “Write a report on today’s market prices” disabled grounding offline. | Do not search for pure transformation. A factual fresh report still requires evidence. Do not mistake quoted instructions for user intent. |
| Explicit web research | Explicit search routes after Hype and URL precedence and after the non-factual exclusion. | Preserve clear user search intent. Keep dedicated long-running research explicit and separate. |
| Documents and media | Attachments dispatch to workflows, prior content is usually only metadata/summary. | Use referenced authorized document content when available. Ask for reattachment when original evidence is unavailable. |
| Multilingual and Hype | Language rules cover several common phrases but model behavior is not guaranteed. Hype mentions can select a dedicated structured path. | Keep language/script and explicit overrides, including mixed-language turns. Use Hype retrieval only for genuinely relevant requests. |

Latest message is explicitly prioritized for language and location, and used alone for route selection. It lacks an authoritative topic boundary or a resolution step for referential evidence. P0 should use deterministic rules for permissions, explicit workflows and hard evidence requirements, with model-native reasoning for interpretation within those boundaries. Evaluate context-aware evidence selection before removing the existing classifier.
